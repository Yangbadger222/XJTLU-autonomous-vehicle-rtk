## 2026.06.29

### [RTK 基础 launch 文件重映射]

#### 涉及文件

- `scripts/launch_with_logs.sh`

#### 变更内容

- 将 `rtk-basic` 的 `LAUNCH_FILE` 参数修改为 `LAUNCH_FILE="system_rtk_basic.launch.py"`（原为 `LAUNCH_FILE="um982_rtk.launch.py"`）
- 移除了 `rtk-basic` 的 `LAUNCH_PACKAGE` 参数（原为 `LAUNCH_PACKAGE="um982_rtk_driver"`）

#### 变更原因

此前 `launch_with_logs.sh` 脚本被设置为直接调用 RTK 驱动功能包中的 launch 文件，而不是主 `bringup` 功能包中的通用系统 launch 文件。此次修改实现了架构上的一致性，统一仅使用 `system_*.launch.py` 文件，从而便于后续扩展以包含其他配置和启动组件。

#### 带来影响

现在运行 `make launch rtk-basic` 会调用 `system_rtk_basic.launch.py`，而该文件内部会进一步调用原本的 `um982_rtk.launch.py`。目前，这对机器人的实际运行没有实质影响。但在代码层面上，它使得后续向 `rtk-basic` 模式中轻松添加其他启动组件（例如 URDF 机器人模型描述）变得更加方便。

- `docs-EN/handoff/rtk_um982_basic_chain.md`
- `docs-CN/knowledge/rtk_fgo.md`
- `docs-EN/knowledge/rtk_fgo.md`

#### Change / 改动

- 将 UM982 `heading_offset_deg` 默认值从 `90.0` 调整为 `88.5`。
- 为 FGO 增加 `heading_quaternion_yaw_is_compass` 参数，默认按当前 `/heading` 的罗盘 heading 编码转换为 ENU yaw 后再进入 frame anchor 与 RTK yaw factor。
- 新增 heading convention 单元测试，覆盖罗盘 heading 到 ENU yaw 的转换、标准 ROS ENU yaw 旁路和 wraparound。

#### Reason / 原因

- 2026-06-24 与 2026-06-29 bag 的 RTK Fixed 直线段显示 raw dual-antenna heading 到车辆行驶罗盘方向的 offset 约为 `88-90 deg`，当前 `90.0` 大方向正确但可能略大。
- Corridor 链路已显式把 `/heading` quaternion yaw 当作罗盘 heading 处理；FGO 原先直接把 quaternion yaw 当 ENU yaw 使用，会把 RTK yaw 因子方向约定混淆。

#### Effect / 影响

- UM982 发布的 `/heading` 更接近已有现场数据估计的车辆 heading。
- FGO shadow mode 的 RTK heading 输入与 GTSAM/ENU yaw 约定一致，后续可更可靠地评估 RTK heading factor。
- `88.5 deg` 仍是 bag-based 初值，后续需要专门直线标定路线确认后再作为最终实车参数。

#### Effect / 影响

#### Change / 改动

- `system_slam.launch.py` 明确为纯建图链路：启动 Livox、FAST-LIO2、pointcloud_to_laserscan、SLAM Toolbox、PGO、map_saver 和 RViz，不启动 Nav2 planner/controller。
- SLAM Toolbox 在建图模式中显式使用 `base_frame=base_link`、`scan_topic=/scan`、`transform_timeout=1.0` 和 `tf_buffer_duration=60.0`，修复默认 `base_footprint` 与当前 FAST-LIO2/scan frame 不一致导致 2D 地图无法保存的问题。
- PGO 增加 `publish_tf` 配置；默认配置保持 `true`，新增 `pgo_slam.yaml` 在纯建图模式下设为 `false`，让 PGO 能保存 3D 地图但不与 SLAM Toolbox 抢 `map -> odom`。
- 新增 `scripts/save_mapping_session.py/.sh`，一键保存 2D 栅格地图、3D PGO 点云地图，并写出 `manifest.yaml`。
- `manifest.yaml` 记录 patch/pose 1:1 完整性、2D/3D 对齐诊断、frame snapshot/check 与 RTK/heading snapshot；`consistency_ok` 由这些保存时检查共同决定，避免坏地图静默进入后续导航或重定位。

#### Reason / 原因

- 室内导航需要 2D Nav2 地图，启动无固定起点重定位需要 3D 点云地图；两者必须在同一个建图 session 中稳定生成并被记录检查。
- 现场测试发现默认 SLAM Toolbox `base_frame=base_footprint`，但实际 `/scan`、FAST-LIO2 odom/TF 使用 `base_link`，导致 `Failed to compute odom pose` 和 2D 保存失败。
- 后续室内外切换需要记录 RTK Fixed 与 heading 用于地理配准，但室内 invalid/float RTK 不能作为强约束直接写入地图优化。

#### Effect / 影响

- `make launch-slam` 的职责收敛为地图资产生产，不承担导航行为。
- `scripts/save_mapping_session.sh <map_name>` 成为推荐保存入口，输出 2D、3D 与 manifest。
- Explore / indoor-nav / nav-gps 等生产导航模式保持 PGO 默认 `publish_tf=true`，不受 slam 专用 `pgo_slam.yaml` 影响。
- 后续实车验证需要在 Jetson 上构建 `pgo` 与 `bringup`，运行 `make launch-slam` 后执行保存脚本，检查 `manifest.yaml` 中 `consistency_ok`、`patch_pose_integrity.ok` 与 `frame_check.ok`。

#### Change / 改动

- 新增 RTK FGO frame anchor 核心与节点 bootstrap 诊断，让原始 RTK ENU fix 必须先显式映射到 FGO `map` 坐标系，再进入普通 innovation gate。
- 将 RTK gate 阈值参数化，包括卫星数、HDOP、强/弱 innovation、heading innovation 和 implied RTK speed。
- 新增 latest-transition wheel planar 因子，让 wheel odom 约束同一个 FAST-LIO keyframe transition，不再额外创建重复图状态。
- 新增可选 IMU 预积分配置和保守的 `ImuFactor` + bias `BetweenFactor` 路径；YAML 默认关闭，等待回放和实车验证。
- 将仅 bookkeeping 的 prune 替换为有界 graph rebuild 诊断，并在 `/rtk_fgo/factor_diagnostics` 中发布 graph 健康字段。
- 新增经过纯 Python 测试的 replay metrics 脚本，解析 `/rtk_fgo/status` 与 `/rtk_fgo/correction_status`。
- 为实验 FGO TF/Nav2 增加显式 launch 参数，默认仍关闭；一旦开启会打印运行时告警。

#### Reason / 原因

- 室内外切换需要稳定的 map-frame anchor 和连续质量 bootstrap，RTK 才能安全拉回局部轨迹。
- 树荫遮挡下，即使接收机仍持续输出 fix，也可能出现质量退化、跳点或物理速度不可能的 RTK 样本；这些样本必须先被质量、innovation 和 implied-speed gate 拒绝，不能进入 shadow graph commit。
- 在调参或考虑任何受保护 TF/Nav2 实验前，必须先有 replay 指标和 graph 诊断。

#### Effect / 影响

- `make launch-tightly-coupled` 默认仍是 shadow mode：不发布生产 `map -> odom`，不 remap Nav2。
- `/rtk_fgo/status` 和 `/rtk_fgo/factor_diagnostics` 现在会解释 anchor bootstrap、RTK 拒绝、wheel factor 和 graph window 状态。
- 当前本地工作站没有 ROS 2 Humble/GTSAM 环境，C++ build/gtest 仍需 Jetson 验证；本地 Python replay parser 测试已通过 `python3 -m pytest scripts/test_rtk_fgo_metrics.py -q`。

#### Change / 改动

- `markRecoveryRejected()` 不再把普通 shadow commit 拒绝永久打入 `FAULT_HOLD`。
- `RTK_RECOVERY` 阶段若候选 RTK Fixed 被 shadow graph 拒绝，回到 `LOCAL_ONLY`，后续仍可通过连续稳定样本重新进入恢复。
- `RTK_LOCKED` 阶段若新候选提交失败，节点会调用降级逻辑进入 `RTK_DEGRADED`。
- 强候选下图残差明确失败仍进入 `FAULT_HOLD`，用于区分图优化异常和普通 RTK 候选拒绝。
- 给 FAST-LIO 新状态的 velocity 与 IMU bias 补 prior，避免最小 GTSAM graph 中新增变量未约束。

- 紧耦合链路的目标是在 Fixed 重新稳定时把轨迹拉回，同时把跳变候选挡在 shadow graph 之外。
- 最小图当前还没有实际 IMU preintegration factor，因此 velocity/bias 变量需要显式 prior 保证优化可解。

#### Effect / 影响

- `rtk_fgo_node` 在 Fixed 抖动后会保留本地解并等待下一轮稳定候选，符合旁路实验模式的安全边界。

- 该修复已通过静态回归测试和本地固件编译；仍必须按抬轮台架流程验证后再进行地面测试。
