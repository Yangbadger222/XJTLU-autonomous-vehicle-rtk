#### Change / 改动

- 新增 C++ `um982_rtk_driver` 包，直接独占 `/dev/rtk_um982`，解析 GGA/RMC/THS/HPR/UNIHEADINGA。
- 发布 `/fix`、`/heading`、`rtk/nmea_sentence` 和 `rtk/status`，保留下游对 `/fix` 的消费方式。
- 增加可选 C++ NTRIP 客户端，默认关闭；CORS 密码只从参数或环境变量读取，不写入仓库。
- 新增 `make launch-rtk-basic` / `system_rtk_basic.launch.py` 做下楼前基础烟测。
- 新增 `make build-rtk-basic`，并让 `rtk-basic` 日志模式直接启动 `um982_rtk_driver`，避免轻量烟测被 `bringup` 的整车运行依赖阻塞。
- 新增 `FYP_RTK_PARAMS_FILE` 现场参数入口，可把临时 CORS/NTRIP YAML 只透传给 UM982 driver。
- `explore-gps`、`nav-gps`、`corridor` 和 `gnss_calibration` 的 GNSS 启动入口切到 C++ UM982 driver。
- runtime 清理流程增加 `um982_rtk_node` 和 `/dev/rtk_um982`。
- 新增 UM982 parser gtest，覆盖 GGA quality 4、THS、HPR、UNIHEADINGA 和坏校验。

#### Reason / 原因

- 现场希望优先用 C++ 准备 RTK 基础链路，减少 Python 常驻进程，并避免单独 monitor/NTRIP 进程抢同一个串口。
- UM982 双天线 heading 可能来自 THS/HPR，也可能来自 Unicore `UNIHEADINGA`，基础链路需要同时支持。
- RTK Fixed/Float 不能只依赖 `NavSatStatus`，必须保留 raw GGA/状态输出供现场判断。

#### Effect / 影响

- 下楼后可先运行 `make launch-rtk-basic`，确认 `/fix`、`/heading`、`rtk/status` 和 raw NMEA，再进入导航模式。
- fresh clone 的 Jetson 可先 `make build-rtk-basic` 完成 RTK 烟测；完整 GPS 导航模式仍按整车栈流程构建。
- 现场可用 `FYP_RTK_PARAMS_FILE=/tmp/um982_cors.yaml` 在基础烟测和 GPS 导航模式之间复用同一份不入库 CORS 参数。
- GPS 相关导航模式默认使用 UM982 `/dev/rtk_um982`，旧 G60 路径保留为回退但不再是主入口。
- 当前 NTRIP 实现支持普通 TCP caster；如果 CORS caster 强制 TLS，需要后续增加 TLS 支持或交给接收机/4G 模块处理。

- 本机无 ROS Humble 环境，只完成无 ROS 核心测试、launch Python 语法、XML 解析、`git diff --check` 和 `make -n build-frc`；仍需在 Jetson 上执行 `colcon build --packages-select frc_msgs frc_nodes_cpp frc_bringup --symlink-install --parallel-workers 1`。

### [下位机急停倒转停止路径修复]

- `docs-CN/commands.md`
- `docs-EN/commands.md`
- `docs-CN/known_issues.md`
- `docs-EN/known_issues.md`

#### Change / 改动

- KEY 急停分支不再停跑后只闪灯，而是持续调用 `Emergency_Stop_Output()` 下发零电流 CAN 帧，并改为非阻塞红灯常亮。
- `Set_free;` / `led_white_start;` 无效表达式修复为函数调用，新增 `Emergency_Stop_Output()` 统一清零 `Vcx/Wc`、目标转速、PID 输出和目标。
- PS2 `B` 键从 PID 锁零速语义改为与 `X` 一致的撤力失能路径，并立即发送零电流帧。
- `pid.c` 恢复积分限幅、`last_err` 更新，并对 PID 时间步长做 1-50 ms 钳位；固件 Makefile 增加 `-Werror=unused-value`。
- 新增不依赖 ROS 的静态回归测试，锁定 KEY/B/X 停止路径与 PID 安全契约。
- 更新安全文档，明确 `X` 仍是最高优先级软件失能，红色物理急停覆盖所有软件命令，`B` 在台架/车测验证前不得替代急停。

#### Reason / 原因

- 旧 KEY 路径会设置 `stop_flag` 后停止任务调度，导致底盘 CAN 不再持续刷新，C620 可能锁存最后一帧电流。
- 旧 `Set_free;` 只是函数名表达式，不会真正调用零电流输出和 PID 清零逻辑。
- 旧 `B` 键通过 PID 锁零速主动刹车，配合未生效的积分限幅会造成过零后的反向电流输出。

#### Effect / 影响

- KEY、`X`、`B` 和手柄掉线停止路径都应进入零电流撤力滑停，而不是停发 CAN 或依赖 PID 抱死。
- 正常串口/手柄行驶路径的 PID 增益值未调整，但积分限幅现在生效；如台架发现跟踪变化，应单独评估 `IntegralLimit`，不要回滚停止路径安全修复。
- 该修复已通过静态回归测试和本地固件编译；仍必须按抬轮台架流程验证后再进行地面测试。

#### Change / 改动

- 分层构建目标补入 `frc_msgs`，并统一加 `--parallel-workers 1`。
- `FRC_MODE=off|shadow|full` 接入 Explore 与 Explore-GPS；`FRC_EXTRA_PARAMS` 可追加 FRC 参数覆盖文件。
- `master_params.yaml` 新增 FRC 在线节点参数节与 PGO `"frc.*"` 导出参数。
- `init_runtime_data.sh` 创建 `runtime-data/frc/{models,routes,trials,events,anchor_log}`。
- `record_bag.sh` 新增 `PROFILE=frc`，追加 FRC、costmap、PGO keyframes、退化度量和 Nav2 状态 topic，优先写入 `$FYP_LOG_SESSION_DIR/rosbag2`，并启用 zstd file compression。
- `nav2_explore.yaml` local costmap 注册 `frc_layer`，默认 `enabled=false`。
- 新增中英文 FRC 知识页，记录运行模式、topic、参数覆盖、录包方式和 costmap 注入安全不变量。

#### Reason / 原因

- FRC 在线节点需要 `frc_msgs` 先构建，否则 `serial_reader` 与 `pgo` 的分层构建会缺接口依赖。
- `shadow` 与 `full` 必须使用相同在线节点集，唯一差异应是 `frc_layer.enabled`，这样 shadow bag 与闭环 bag 才能同构对比。
- `frc_layer` 是 tuned YAML 改动，默认旁路可保证基线行为不因装载插件而改变；闭环实验通过 `/frc/enable` 显式进入。
- FRC 数据闭环依赖统一 session 目录、FRC runtime 子目录和固定录包 profile。

#### Effect / 影响

- `make build-sensor`、`make build-perception`、`make build-frc` 的依赖关系更完整，并符合 Jetson 单 worker 构建约束。
- `FRC_MODE=shadow make launch-explore` 可启动 FRC 在线观测链而不注入 costmap。
- `FRC_MODE=full make launch-explore` 会延时调用 `/frc/enable` 打开风险注入。
- `PROFILE=frc bash scripts/data_collection/record_bag.sh` 可采集后续离线挖掘、BEV 构建和实验指标所需 topic，并与当前日志 session 对齐。
- 后续若调整 `frc_layer` 或 FRC 参数，必须同步更新本知识页与 devlog。
