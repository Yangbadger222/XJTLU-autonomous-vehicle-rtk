#### Change / 改动

- 为 `/rtk_fgo/factor_diagnostics` 增加结构化字段：RTK GGA quality、收星数、HDOP、position/heading innovation、fix 隐含速度和各输入 age。
- 扩展 `scripts/evaluate_rtk_fgo_bag.py`，在 replay JSON metrics 中汇总这些诊断字段。
- 增加 `FrameAnchor::enuYawToMapYaw()`，在 heading innovation 检查和 yaw factor 插入前，把 RTK heading 旋转到 FGO `map` frame。
- 增加支持 wraparound 的 heading stability 检查，用于 frame-anchor bootstrap，并把 `max_heading_spread_deg` 移到 `frame_anchor` 参数组。

#### Reason / 原因

- 回放 `reloc_enu_align_20260629_183500` 发现 heading innovation 在比较 FAST-LIO/FGO map-frame yaw 与原始 RTK ENU yaw；而 RTK position 已经经过 frame anchor 旋转，二者 frame 不一致。
- 同一段回放还显示 anchor bootstrap 时双天线 heading 出现瞬时跳变。YAML 已写了 heading spread 阈值，但节点没有声明、读取或执行该限制。
- 原有 replay metrics 不足以区分收星质量、输入 age、frame 约定和 bootstrap 问题。

#### Effect / 影响

- 干净 replay 指标从 `3` 个 strong candidate、`0` 个 locked 样本、`419` 次 heading reject，提升为 `129` 个 strong candidate、`102` 个 locked 样本、`69` 次 heading reject。
- 稳定 heading bootstrap 后 position innovation 在该 bag 中保持可控（`median 1.38 m`、`max 2.96 m`），避免了错误 anchor 情况下的十几米级偏差（`median 16.25 m`、`max 25.84 m`）。
- FGO 默认仍保持 shadow-only；当前 replay 结果支持继续实车验证，但还不能直接让 FGO 接管生产 `map -> odom`。

#### Change / 改动

- 恢复 `travel` 为实验性先验地图导航链路：`map_yaml` 注入 Nav2 `map_server`，`pcd_map` 传给 `localizer` 预加载 PCD。
- `localizer` 支持启动时加载 PCD，并保留 `/localizer/relocalize` 服务用于现场重载地图和设置初始位姿。
- `nav2_travel.yaml` 改为由 `localizer` 负责 `map -> odom`，AMCL `tf_broadcast=false`；全局 costmap 恢复 `static_layer` 并关闭 rolling window。
- `launch_with_logs.sh` 支持透传额外 launch 参数，`travel` 也支持 `FYP_USE_RVIZ`。

#### Reason / 原因

- Nav2 标准先验地图导航需要 2D OccupancyGrid 做全局规划，但当前需求是用先验 PCD 做上电/运行时重定位；两者需要在 `travel` 中接成同一条链。
- `map -> odom` 只能有一个发布者。Travel 模式必须避免 AMCL、PGO 和 `localizer` 同时抢 TF。
- 旧 `travel` 参数中 `map_server.yaml_filename` 为空，且 `localizer` 只是独立工具，没有接入系统 launch。

#### Effect / 影响

- 现场可用 `bash scripts/launch_with_logs.sh travel map_yaml:=... pcd_map:=...` 启动先验地图链路。
- 运行时 TF 约定为 `localizer: map -> odom`、`FAST-LIO2: odom -> base_link`；PGO 默认关闭，或只以 `publish_tf=false` 辅助可视化/保存地图。
- 本地已通过源码合同测试与 Python launch 语法检查；完整 ROS 2 Humble 构建和室内实车先验地图验证仍需在 Jetson 上完成。

### [Travel 运行清理补齐 localizer 与 ros2 launch]

#### File / 文件

- `Makefile`
- `scripts/launch_with_logs.sh`
- `src/bringup/test/test_system_travel_launch.py`

#### Change / 改动

- `make kill-runtime` 的清理正则新增 `[r]os2 launch` 与 `[l]ocalizer_node`。
- `scripts/launch_with_logs.sh` 的启动前/退出清理同样新增 `[r]os2 launch` 与 `[l]ocalizer_node`。
- 增加测试覆盖 travel 运行清理必须包含直接 `ros2 launch` 进程和 `localizer_node`。

#### Reason / 原因

- 实车 travel 测试中发现旧 `system_slam.launch.py`、旧 `system_travel.launch.py` 和多个 `/localizer/localizer_node` 可同时残留。
- 残留 localizer 会导致 ROS graph、service 和 TF 行为混乱；Nav2 controller 日志出现 `base_link -> odom` TF 不存在后，navigation lifecycle 被关闭，RViz 点目标后车辆不动。

#### Effect / 影响

- 后续 `make kill-runtime` 和 `scripts/launch_with_logs.sh` 启动前清理会覆盖 travel localizer 与直接启动的 ROS launch 父进程。
- 降低现场反复切换 slam/travel 后出现重复节点、旧 TF 发布者和 Nav2 不执行目标的概率。

### [Travel localizer 抑制未验证与旧时间戳 TF]

#### File / 文件

- `src/perception/localizer/src/localizer_node.cpp`
- `src/perception/localizer/config/localizer.yaml`
- `src/perception/localizer/test/test_localizer_contract.py`
- `docs-CN/commands.md`
- `docs-EN/commands.md`
- `docs-CN/architecture.md`
- `docs-EN/architecture.md`

#### Change / 改动

- `localizer` 启动预加载 PCD 后不再立即广播 `map -> odom`，必须等待 `/localizer/relocalize` 成功。
- 移除 timer 非更新周期对同一 `last_message_time` 的重复 TF 广播。
- 增加 `max_tf_input_age_s`，跳过明显过期输入 stamp，并记录最后一次已发布 TF stamp，避免重复/倒退的 `map -> odom`。
- 更新 Travel 运行说明，明确先验证 `odom -> base_link`，再 relocalize，最后检查 `map -> odom`。

#### Reason / 原因

- 现场日志出现 `TF_OLD_DATA ignoring data from the past for frame odom at time 1782993113.484190`，同时 `tf2_echo odom base_link` 显示 FAST-LIO 当前 TF 已恢复到小幅米级变化。
- 根因是 `localizer` 在未完成重定位时也会发布 `map -> odom`，且 10ms timer 会在 1Hz ICP 更新间隔内重复广播同一旧 stamp，污染 Nav2 TF buffer。

#### Effect / 影响

- Travel 启动后不会再用未验证的 identity/旧 stamp `map -> odom` 抢占 TF。
- 操作顺序更严格：启动 travel -> 验证 FAST-LIO `odom -> base_link` -> 调 `/localizer/relocalize` -> `relocalize_check` 为 true -> 再发 Nav2 goal。
