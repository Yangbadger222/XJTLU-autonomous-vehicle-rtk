#### 原因

- **勘测自主化需求**：此前探索未知环境和匹配地图位姿主要依赖手动遥控。引入勘测模式可实现完全自主的前沿探索，并自动查询既有地图数据库，判定环境是已知还是需纯新建图。
- **TF 仲裁与多源定位协调**：此前版本中，AMCL 与 3D 激光定位器同时发布或跳变式更新 TF 会产生超 20 厘米的瞬间跳变，直接导致 NavFn 在膨胀层内规划失败以及 Foxglove 界面抖动。
- **全链路多层级安全屏障**：在上位机卡死、导航异常或串口断连时，此前缺乏硬件级超时兜底，可能引发车辆失控飞车；此外避障减速转弯时极易发生低于物理死区的堵转磨损。
- **高层人机交互与状态感知**：操作人员此前缺少便捷的命名目标点导航接口与可视化监控界面，无法直观发送类似“会议室”、“充电桩”的目标并实时获知导航状态。
- **2D/3D 先验地图一致性保障**：原始 2D 栅格地图与 3D 点云往往存在未知坐标偏移和激光噪点。建立量化验收门禁（RMSE、重叠率）的室内地图包体系，是保证室内精准定位与导航的前提。

#### 效果

- **全流程无缝启动**：勘测与 Travel 模式均可通过单条标准 launch 指令启动（`system_survey.launch.py`、`system_travel.launch.py`），打通了从自主探索、地图匹配到定点导航的全流程。
- **平滑无跳变的室内定位**：通过 `prior_map_tf_authority` 实现平滑限速的 SE(2) 校正，彻底消除了 AMCL 与 3D 定位器冲突，杜绝了规划起点自锁与界面抖动。
- **故障闭锁级安全保障**：任一传感器断流、定位降级、软件卡死或串口断连均可在节点层（`localization_cmd_gate`、`serial_twistctl`）和嵌入式固件层（500ms 看门狗）无延迟触发急停闭锁。
- **直观便捷的操作体验**：支持通过 Foxglove 2D 目标点击或命名目的地一键发起导航，并提供实时状态反馈、可视化标记与平滑取消控制。
- **高质量自动化地图包**：单脚本一键生成包含滤波 2D 栅格、高精度对齐 3D 点云及 Scan Context 描述子的标准化室内地图包。
- **整洁高效的构建输出**：清除了所有 Python 与 C++ 编译警告，提升了代码仓库的长期可维护性。
