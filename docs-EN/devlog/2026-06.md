### [Lower-Controller Stop-Path Wheel-Reversal Fix]

#### File

- `src/firmware/rm_c_board/Core/Src/main.c`

- `docs-CN/commands.md`
- `docs-EN/commands.md`
- `docs-CN/known_issues.md`
- `docs-EN/known_issues.md`

#### Change

- Changed the KEY stop branch from task shutdown plus blocking LED blink to sustained `Emergency_Stop_Output()` zero-current CAN output with a non-blocking solid red LED.
- Replaced invalid `Set_free;` / `led_white_start;` expressions with real function calls, and added `Emergency_Stop_Output()` to clear `Vcx/Wc`, target wheel speeds, PID outputs, and PID targets.
- Changed PS2 `B` from PID zero-speed braking to the same coast-stop disable path as `X`, with immediate zero-current output.
- Restored PID integral limiting and `last_err` updates, clamped PID step time to 1-50 ms, and added `-Werror=unused-value` to the firmware Makefile.
- Added a ROS-free static regression test for the KEY/B/X stop paths and PID safety contract.
- Updated safety docs to state that `X` remains the highest-priority software disable, the red physical e-stop overrides all software commands, and `B` must not replace those stops before bench and vehicle validation.

#### Reason

- The old KEY path set `stop_flag` and stopped task scheduling, so chassis CAN commands were no longer refreshed and the C620 controllers could latch the last current frame.
- The old `Set_free;` statements only evaluated a function name expression; they did not send zero current or clear PID state.
- The old `B` path used PID zero-speed braking, and disabled integral limiting could keep producing reverse current after wheel speed crossed zero.

#### Effect

- KEY, `X`, `B`, and gamepad-loss stop paths should now enter zero-current coast stop instead of stopping CAN output or relying on PID braking.
- Normal serial/gamepad driving PID gains are unchanged, but integral limiting is now active; if bench testing shows tracking changes, evaluate `IntegralLimit` separately instead of reverting the stop-path safety fix.
- The fix passed static regression tests and local firmware compilation; wheel-off bench validation is still required before ground testing.

#### Change

- Added `frc_msgs` to layered build targets and made the targets use `--parallel-workers 1`.
- Wired `FRC_MODE=off|shadow|full` into Explore and Explore-GPS; added `FRC_EXTRA_PARAMS` for appended FRC parameter overrides.
- Added FRC online-node parameter sections and PGO `"frc.*"` export parameters to `master_params.yaml`.
- Made `init_runtime_data.sh` create `runtime-data/frc/{models,routes,trials,events,anchor_log}`.
- Added `PROFILE=frc` to `record_bag.sh`, appending FRC, costmap, PGO keyframe, degeneracy, and Nav2 status topics, defaulting output to `$FYP_LOG_SESSION_DIR/rosbag2`, and using zstd file compression.
- Registered `frc_layer` in the `nav2_explore.yaml` local costmap with `enabled=false` by default.
- Added bilingual FRC knowledge docs covering runtime modes, topics, parameter overrides, bag recording, and costmap injection safety invariants.

#### Reason

- FRC online nodes require `frc_msgs` to be built first; otherwise layered `serial_reader` and `pgo` builds miss their new interface dependency.
- `shadow` and `full` must run the same online node set, with `frc_layer.enabled` as the only behavior difference, so shadow and closed-loop bags remain structurally identical.
- `frc_layer` is a tuned YAML change. Keeping it disabled by default preserves baseline behavior until `/frc/enable` explicitly turns on injection.
- The FRC data loop needs a shared session layout, runtime subdirectories, and a fixed recording profile.

#### Effect

- `make build-sensor`, `make build-perception`, and `make build-frc` now have complete dependency entrypoints and follow the Jetson single-worker build constraint.
- `FRC_MODE=shadow make launch-explore` can start the FRC observation path without costmap injection.
- `FRC_MODE=full make launch-explore` delays and then calls `/frc/enable` to enable risk injection.
- `PROFILE=frc bash scripts/data_collection/record_bag.sh` records the topics required for offline mining, BEV generation, and trial metrics while staying aligned with the current log session.
- Future FRC parameter or `frc_layer` tuning changes must update the knowledge page and devlog together.
