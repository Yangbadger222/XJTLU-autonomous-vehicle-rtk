#### Change

- Added `frc_msgs` to layered build targets and made the targets use `--parallel-workers 1`.
- Wired `FRC_MODE=off|shadow|full` into Explore and Explore-GPS; added `FRC_EXTRA_PARAMS` for appended FRC parameter overrides.
- Added FRC online-node parameter sections and PGO `"frc.*"` export parameters to `master_params.yaml`.
- Made `init_runtime_data.sh` create `runtime-data/frc/{models,routes,trials,events,anchor_log}`.
- Added `PROFILE=frc` to `record_bag.sh`, appending FRC, costmap, PGO keyframe, degeneracy, and Nav2 status topics, defaulting output to `$FYP_LOG_SESSION_DIR/rosbag2`, and using zstd file compression.
- Registered `frc_layer` in the `nav2_explore.yaml` local costmap with `enabled=false` by default.
- Added bilingual FRC knowledge docs covering runtime modes, topics, parameter overrides, bag recording, and costmap injection safety invariants.

#### Reason

- FRC online nodes require `frc_msgs` to be built first; otherwise layered `serial_reader` and `pgo` builds miss their new interface dependency.
- `shadow` and `full` must run the same online node set, with `frc_layer.enabled` as the only behavior difference, so shadow and closed-loop bags remain structurally identical.
- `frc_layer` is a tuned YAML change. Keeping it disabled by default preserves baseline behavior until `/frc/enable` explicitly turns on injection.
- The FRC data loop needs a shared session layout, runtime subdirectories, and a fixed recording profile.

#### Effect

- `make build-sensor`, `make build-perception`, and `make build-frc` now have complete dependency entrypoints and follow the Jetson single-worker build constraint.
- `FRC_MODE=shadow make launch-explore` can start the FRC observation path without costmap injection.
- `FRC_MODE=full make launch-explore` delays and then calls `/frc/enable` to enable risk injection.
- `PROFILE=frc bash scripts/data_collection/record_bag.sh` records the topics required for offline mining, BEV generation, and trial metrics while staying aligned with the current log session.
- Future FRC parameter or `frc_layer` tuning changes must update the knowledge page and devlog together.
