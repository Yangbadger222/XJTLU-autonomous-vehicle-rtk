#### Change

- Added structured `/rtk_fgo/factor_diagnostics` fields for RTK GGA quality, satellite count, HDOP, position and heading innovations, implied fix speed, and input ages.
- Extended `scripts/evaluate_rtk_fgo_bag.py` to summarize those diagnostic fields in replay JSON metrics.
- Added `FrameAnchor::enuYawToMapYaw()` and now rotate RTK heading measurements into the FGO `map` frame before heading innovation checks and yaw-factor insertion.
- Added wraparound-safe heading stability checks for frame-anchor bootstrap and moved `max_heading_spread_deg` under the `frame_anchor` parameter group.

#### Reason

- Replay of `reloc_enu_align_20260629_183500` showed that heading innovations were being computed between FAST-LIO/FGO map-frame yaw and raw RTK ENU yaw, while RTK positions were already rotated through the frame anchor.
- The same replay showed a transient dual-antenna heading jump during anchor bootstrap. The YAML already documented a heading-spread threshold, but the node did not read or enforce it.
- Existing replay metrics did not expose enough RTK quality, age, and innovation detail to distinguish satellite quality problems from frame-convention and bootstrap problems.

#### Effect

- Clean replay metrics improved from `3` strong candidates, `0` locked samples, and `419` heading rejects to `129` strong candidates, `102` locked samples, and `69` heading rejects.
- Position innovation after stable-heading bootstrap stayed bounded in the replay (`median 1.38 m`, `max 2.96 m`) instead of rising to the bad-anchor case (`median 16.25 m`, `max 25.84 m`).
- FGO remains shadow-only by default; the replay result supports further field validation but is not yet a reason to let FGO own production `map -> odom`.
