#### Change

- Added structured `/rtk_fgo/factor_diagnostics` fields for RTK GGA quality, satellite count, HDOP, position and heading innovations, implied fix speed, and input ages.
- Extended `scripts/evaluate_rtk_fgo_bag.py` to summarize those diagnostic fields in replay JSON metrics.
- Added `FrameAnchor::enuYawToMapYaw()` and now rotate RTK heading measurements into the FGO `map` frame before heading innovation checks and yaw-factor insertion.
- Added wraparound-safe heading stability checks for frame-anchor bootstrap and moved `max_heading_spread_deg` under the `frame_anchor` parameter group.

#### Reason

- Replay of `reloc_enu_align_20260629_183500` showed that heading innovations were being computed between FAST-LIO/FGO map-frame yaw and raw RTK ENU yaw, while RTK positions were already rotated through the frame anchor.
- The same replay showed a transient dual-antenna heading jump during anchor bootstrap. The YAML already documented a heading-spread threshold, but the node did not read or enforce it.
- Existing replay metrics did not expose enough RTK quality, age, and innovation detail to distinguish satellite quality problems from frame-convention and bootstrap problems.

#### Effect

- Clean replay metrics improved from `3` strong candidates, `0` locked samples, and `419` heading rejects to `129` strong candidates, `102` locked samples, and `69` heading rejects.
- Position innovation after stable-heading bootstrap stayed bounded in the replay (`median 1.38 m`, `max 2.96 m`) instead of rising to the bad-anchor case (`median 16.25 m`, `max 25.84 m`).
- FGO remains shadow-only by default; the replay result supports further field validation but is not yet a reason to let FGO own production `map -> odom`.

#### Change

- Restored `travel` as an experimental prior-map navigation chain: `map_yaml` is injected into Nav2 `map_server`, and `pcd_map` is passed to `localizer` for startup PCD loading.
- `localizer` can now load a PCD map at startup while keeping `/localizer/relocalize` for field map reloads and initial-pose updates.
- `nav2_travel.yaml` now lets `localizer` own `map -> odom`, sets AMCL `tf_broadcast=false`, restores the global costmap `static_layer`, and disables global rolling window mode.
- `launch_with_logs.sh` now forwards extra launch arguments and lets `travel` honor `FYP_USE_RVIZ`.

#### Reason

- Standard Nav2 prior-map navigation uses a 2D OccupancyGrid for global planning, but this use case also needs prior PCD relocalization at startup/runtime; both assets must be wired into the same `travel` chain.
- `map -> odom` must have exactly one publisher. Travel mode must prevent AMCL, PGO, and `localizer` from competing for that TF.
- The old `travel` config left `map_server.yaml_filename` empty, and `localizer` existed only as a standalone tool rather than a system launch component.

#### Effect

- Operators can start the prior-map chain with `bash scripts/launch_with_logs.sh travel map_yaml:=... pcd_map:=...`.
- Runtime TF convention is `localizer: map -> odom` and `FAST-LIO2: odom -> base_link`; PGO is off by default or runs only with `publish_tf=false` for visualization/map-saving support.
- Local source-contract tests and Python launch syntax checks pass; full ROS 2 Humble build and indoor prior-map vehicle validation still need to run on the Jetson.

#### File

#### Change

- Added `[r]os2 launch` and `[l]ocalizer_node` to the `make kill-runtime` cleanup pattern.
- Added the same `[r]os2 launch` and `[l]ocalizer_node` coverage to `scripts/launch_with_logs.sh` startup/exit cleanup.
- Added a regression test requiring travel runtime cleanup to include direct `ros2 launch` processes and `localizer_node`.

#### Reason

- Field travel testing showed old `system_slam.launch.py`, old `system_travel.launch.py`, and multiple `/localizer/localizer_node` processes could remain alive together.
- Stale localizers make the ROS graph, services, and TF tree ambiguous; Nav2 controller logs showed missing `base_link -> odom` TF, after which the navigation lifecycle shut down and RViz goals did not move the vehicle.

#### Effect

- Future `make kill-runtime` and `scripts/launch_with_logs.sh` startup cleanup now cover the travel localizer and direct ROS launch parent processes.
- Reduces repeated-node, stale-TF-publisher, and non-executing Nav2-goal failures after switching between slam/travel in field tests.
